ask(text, r)
ฟังก์ชันกลางที่การถามทุกแบบมาผ่าน:
  1. ถ้ากำลังยุ่ง (busy) หรือคำถามหมดจะไม่ทำอะไร
  2. จำ target ไว้ก่อน เผื่อผู้เล่นสลับไปดูคนอื่นระหว่างรอ
  3. หักคำถาม 1 ข้อ แล้วใส่ข้อความของผู้เล่นลงแชท
  4. ตั้ง thinking ให้ขึ้น "..."
  5. ผ่านไป 700ms ให้ผู้ต้องสงสัยพูด r.text, เปลี่ยน mood และถ้ามีโน้ตก็เพิ่มลงแฟ้มคดี (ไม่เพิ่มถ้าซ้ำ)

askText(text)

lib (วาด pixel art)

src/lib/pixel.tsPure

วาดภาพทุกอย่างด้วยโค้ด ไม่มีไฟล์รูปเลย ภาพคนเป็นอาร์เรย์สี 64×64 ช่อง (Px) เลือกสีทีละ pixel จากรูปทรงคณิตศาสตร์ เช่นวงรี แล้วลงเงาด้วย dithering (ลายตารางหมากรุกสลับ 2 สี) แทน gradient ตามกฎงานภาพ

W · K · Who · Mood · Px · Fn
W = 64 คือขนาดรูปคน, K = สีเส้นขอบ #1A1414, Px = อาร์เรย์สี (null = ว่าง), Fn = ฟังก์ชันที่ตอบว่าพิกัด (x,y) อยู่ในรูปทรงหรือเปล่า
chk(x, y) → boolean
คืน true ถ้า (x+y) เป็นเลขคู่ ได้ลายตารางหมากรุก ใช้เป็นฐานของ dithering ทุกจุด
SKIN · CLOTH · HAIR
ชุดสีของแต่ละตัวละคร มี 3 ระดับ [สว่าง, กลาง, เงา]
shade(x, y, u, c) → สี
เลือกสีจากค่า u ที่บอกว่าจุดนี้อยู่ฝั่งสว่าง (ติดลบ) หรือฝั่งเงา (บวก) ตามแสงไฟที่มาจากซ้ายบน ระหว่างแต่ละระดับมีแถบที่ใช้ chk สลับ 2 สี จึงเปลี่ยนสีได้นุ่มแบบเกม 16-bit
paint(b, t, f)
ไล่ทุก pixel ถ้า t(x,y) บอกว่าอยู่ในรูปทรง จะใส่สีจาก f(x,y) ลงใน buffer b
outer(b, t)
วาดเส้นขอบหนา 1px รอบรูปทรง โดยหา pixel ที่อยู่นอกรูปทรงแต่ติดกับรูปทรงทางบน ล่าง ซ้าย หรือขวา แล้วระบายเป็นสี K (ตามกฎ "1px dark outlines")
set(b, x, y, c)
เขียนสีลง pixel เดียว เช็กก่อนว่าไม่หลุดขอบภาพ
bgPixel(x, y)
พื้นหลังของรูปคน: แสงโคมไฟที่มุมซ้ายบน ใช้ระยะห่าง Math.hypot แบ่งเป็นวงสีเหลือง → ส้ม → น้ำตาล → น้ำเงินเข้ม มี dithering คั่นระหว่างวง และมีแถบมู่ลี่ทางขวา
renderPortrait(who, mood, blink, sweatY) → Px
วาดคนทีละชั้นจากหลังมาหน้า:
  1. ลำตัวและชุด (คอวีของ Voss, เนคไทของ Pike, หูกระต่ายของ Doyle)
  2. ผมยาวด้านหลัง (เฉพาะ Voss)
  3. คอ หู และหัว ซึ่งเป็นวงรีจากสมการ (x/a)²+(y/b)² ≤ 1
  4. จมูก หนวด และเครา
  5. ทรงผมของแต่ละคน
  6. ตา: blink = หลับตาเป็นเส้น, broken = เปลือกตาหนัก, Doyle จะหลบตาเสมอยกเว้นตอนโกรธ
  7. คิ้วเอียงตาม mood (โกรธ = ขมวดลง, กังวล = ยกขึ้น)
  8. แว่นของ Pike วาดเป็นวงแหวนจากระยะห่างที่ใกล้ 4.4 pixel
  9. ปากตาม mood
  10. หยดเหงื่อที่ตำแหน่ง sweatY
สุดท้ายเติม pixel ที่ยังว่างด้วย bgPixel
drawBackdrop(ctx)
วาดฉากหลังขนาด 360×225 ลง canvas เป็นวงแสงรูปวงรี (หารแกน x ด้วย 1.6 ให้ยืดตามแนวนอน) มืดลงเป็นขั้นๆ พร้อม dithering แล้วโรยฝุ่นสีส้ม 16 จุดด้วยตัวสุ่มเทียมแบบ LCG ที่ใช้ seed 7 ตายตัว จึงได้ตำแหน่งเดิมทุกครั้ง
SPRITE_PAL · SPRITES

interface LlmProvider · generate(req)

DummyProvider · llm
ตอนนี้คืนประโยคตายตัว และ llm คือ provider ที่ทั้งโปรแกรมใช้
src/http/errors.ts
class HttpError(status, code, message)
error ที่รู้ว่าควรตอบ HTTP status อะไร เช่น 403 + LAWYERED_UP
notFound(what)
ตัวช่วยสร้าง HttpError 404 เช่น "Session not found"
parseId(id, what)
id ใน URL ต้องเป็น UUID ถ้าไม่ใช่ แปลว่าไม่มีทางมีอยู่จริง จึง throw 404 ทันทีโดยไม่ถาม DB (Postgres จะ error ถ้าส่ง id ที่ไม่ใช่ UUID เข้าไป)
errorHandler
แปลง error ทุกชนิดเป็น JSON รูปแบบเดียวกัน { error: { code, message } }:
  • HttpError → ตาม status ที่กำหนด
  • ZodError (body ไม่ถูกต้อง) → 400 พร้อมรายการจุดที่ผิด
  • อย่างอื่น → log ไว้ฝั่ง server แล้วตอบ 500 ข้อความกลางๆ ไม่ส่งรายละเอียดภายในออกไป

Services (เชื่อม engine + llm + db)

src/services/publicView.tsกันข้อมูลรั่ว

response ทุกอันต้องผ่านฟังก์ชันในไฟล์นี้ ใช้วิธีเลือกเฉพาะฟิลด์ที่อนุญาต (whitelist) แทนการลบฟิลด์ลับออก (blacklist) ถ้าวันหน้าเพิ่มฟิลด์ลับใหม่เข้า schema มันจะไม่หลุดออกไปเอง

toPublicCaseSummary(c)
id, slug, title, number สำหรับหน้ารายการคดี
toPublicCase(c)
สรุปคดี + ผู้ต้องสงสัย (ไม่รวม closer) + หลักฐาน และไม่มีคอลัมน์ความจริงของคดี (culpritId, verdict, reactions) เลย
toPublicSession(s)
สถานะ session และ state รายคน ไม่รวม version, commitments และ position
src/services/caseService.ts
listCases()
ดึงคดีทั้งหมด โดยใช้ select เอามาแค่ 4 ฟิลด์ตั้งแต่ตอน query ไม่ได้ดึงคอลัมน์ความจริงของคดีออกมาจาก DB เลย
getCase(id)
ดึงคดีเดียว ถ้าไม่เจอ throw 404 แล้วส่งผ่าน toPublicCase
src/services/sessionService.tsDummy บางส่วน
reactionSchema · reactionsSchema
zod schema สำหรับตรวจ reactions ของคดีที่เก็บเป็น Json (Prisma ไม่รู้รูปแบบข้างใน) ตรวจก่อนใช้จะได้ type ที่ถูกต้อง และรู้ทันทีถ้าข้อมูลใน DB ผิดรูปแบบ
loadSession(id)
ดึง session พร้อมข้อมูลคดีและแถว state ของผู้ต้องสงสัย (sessionWithCase) ถ้าไม่เจอ throw 404
toEngineState(row)
แปลงแถว suspect_states เป็น SuspectState ธรรมดาของ engine โดยตัด sessionId/position ออก จะได้ไม่หลุดเข้า engine และไม่หลุดเข้า snapshot ใน transcript
saveSession(session, { suspect?, status?, accusedId? })
เขียนกลับลง DB แบบ optimistic concurrency คืออัปเดตเฉพาะเมื่อ version ใน DB ยังเท่ากับตอนที่อ่านมา และบวก version เพิ่ม 1 ถ้าระหว่างนั้นมี request อื่นเขียนไปก่อน (เช่นกดถามรัวๆ 2 ครั้งพร้อมกัน) version จะไม่ตรง ได้ count === 0 แล้วตอบ 409 การเช็ก version กับการอัปเดตแถว suspect อยู่ใน transaction เดียวกัน ถ้าชนกัน ทั้งสองอย่างถูกยกเลิกพร้อมกัน วิธีนี้ทำให้โกงจำนวนคำถามด้วยการยิง request พร้อมกันไม่ได้
createSession(caseId)
สร้าง session ใหม่พร้อมแถว state ของทุกคนที่เริ่มด้วย createSuspectState (ใส่ position ตามลำดับในคดี) และตอนนี้เปิดให้เห็นหลักฐานทุกชิ้นตั้งแต่แรก (Dummy จนกว่าจะมีฉากสืบสวน)
getSession(id)
โหลดแล้วส่งผ่าน toPublicSession
interrogate(sessionId, { suspectId, message, evidenceId? })
ขั้นตอนของหนึ่งตา:
  1. ถ้าคดีจบไปแล้ว ตอบ 409 CASE_OVER
  2. หาผู้ต้องสงสัย ถ้าไม่เจอตอบ 404 ถ้ายื่นหลักฐานที่ยังไม่ได้ค้นพบตอบ 400
  3. spendQuestion หักคำถาม ถ้าหมดแล้วตอบ 403 LAWYERED_UP (นับที่ server เท่านั้น)
  4. (Dummy) แยก intent ง่ายๆ: มีหลักฐาน = confrontation ไม่มี = question
  5. (Dummy) เลือกคำตอบ: ถ้ายื่นซ้ำได้คำตอบ "ยื่นซ้ำ", ถ้ามี reaction ได้ reaction และ mood ใหม่, นอกนั้นเรียก llm.generate
  6. เพิ่มหลักฐานลงใน confrontedEvidence
  7. saveSession แล้วบันทึก transcript (turn = จำนวนตาที่มีอยู่ + 1)
  8. ตอบกลับ reply, kind, note, lawyeredUp และ closer เมื่อเพิ่งหมดคำถาม พร้อม state สาธารณะของคนนี้
accuse(sessionId, accusedId)
เช็กว่าคดียังไม่จบและมีคนนี้อยู่จริง แล้วเรียก judgeAccusation บันทึก status กับ accusedId จากนั้นค่อยเปิดเผยคำอธิบายคดี ซึ่งเป็นจุดเดียวที่ข้อความสรุปคดี (verdictCorrect/verdictWrong) ถูกส่งออกไป และส่งได้เพราะคดีจบแล้ว
